# 아트링크 1.11.7 수정 내역과 배포 전 확인

최종 갱신 2026-09-24 (Claude)

2026-09-23 Codex 작성분에 2026-09-23~24 Claude 작업 내용을 반영했다.
작업 브랜치: `codex/artlink-1.11.7-safety` (main에 빨리감기 병합, HEAD `f62479a`).
앱 버전 1.11.7, iOS 빌드 85, Android versionCode 87.

## 수정한 사용자 문제

- 로그아웃하거나 다른 계정으로 로그인할 때 노트·프로필·포트폴리오·초안·연습 기록이 섞이지 않도록 계정별로 저장한다. 진행 중인 조회와 저장도 계정 경계를 넘지 않는다.
- 새 게스트의 기록은 가입 계정으로 한 번 이관한다. 소유자를 확인할 수 없는 구버전 자료는 원본을 보존하고 자동 합치지 않으며 복구 안내를 표시한다.
- 실제 저장이 실패하면 성공 표시를 하지 않는다. 노트 삭제 실패는 다시 시도하고 삭제한 기록이 동기화로 되살아나는 것을 막는다.
- 녹음·사진은 앱의 영구 저장 폴더로 복사한 뒤 저장한다. 실패 시 원본과 작성 내용을 유지한다. 2인 대사 녹음은 이탈 전에 저장 여부를 확인한다.
- 프로필 사진 전체 목록·대표 순서를 유지하고 파일 이름 충돌을 피한다.
- 오디오 전사가 실패하면 오디오를 빼고 AI 분석을 진행하지 않는다. 스트림의 명시적 완료를 확인해야 결과를 성공으로 처리한다.
- AI 생성 후 로컬 저장만 실패하면 생성 결과를 화면에 유지한다. ‘저장 다시 시도’는 AI 요청이나 이용 횟수 차감을 다시 하지 않는다. 앱 강제 종료까지 보장하는 서버 결과 보관은 별도 과제다.
- 신규 학습 자료 수집은 중단한다. 운영 통계에 자유 입력 제목·태그·피드백 본문을 보내지 않는다. 기존 device_id 통계는 남으므로 완전한 익명화를 구현했다고 표현하지 않는다.
- 동의 철회는 로그인 계정 미디어 보관함의 삭제 완료를 확인한 경우에만 해당 범위의 완료를 안내한다. 실패 후 재시도 버튼을 제공한다.

## 2026-09-23~24에 추가한 것 (Claude)

### 회원 탈퇴

- `src/services/accountDeleteService.js` 신설. 서버 `/api/account-delete`를 호출하고 응답을 해석한다.
- `AppContext.handleDeleteAccount`는 서버가 `complete:true`를 돌려준 경우에만 `clearAccountStorage(scope)` 후 로그아웃한다. 실패하면 기기 자료와 로그인 상태를 그대로 두고 ‘다시 시도’ 버튼과 남은 항목을 보여 준다.
- 서버가 돌려준 `excludes`·`failed` 코드는 `ProfileScreen`에서 번역 키로 바꿔 보여 준다. 영문 코드를 그대로 노출하지 않는다.
- 비로그인 상태에서는 탈퇴 API를 호출하지 않는다.

### 프로필 공개 OFF

- `profileService.syncProfileVisibility`(`_visibilityOnly`)로 토글 시점에 바로 서버에 보낸다.
- 전송 실패는 `visibilityPending`으로 영속 저장하고 포그라운드 복귀·다음 실행에서 재시도한다.
- 모든 프로필 업로드에 단조 증가하는 `visibilityUpdatedAt`을 함께 보낸다.
- `adoptServerVisibility`로 서버 응답의 공개 상태가 더 새로우면 기기가 그것을 따른다. 다른 기기에서 끈 비공개를 이 기기가 되돌리지 못한다.
- 편집 화면에 ‘비공개 적용 중’ 표시를 넣었다.

### 소유자 불명 구버전 기록

- `LegacyRecoveryScreen` 신설. 요약을 먼저 보여 주고, 사용자가 ‘내 기록이 맞다’ 스위치를 직접 켜야 옮기기가 활성화된다.
- 원본은 보존하고 안내를 반복해서 띄우지 않는다. 서버에서 남의 자료를 끌어오는 경로는 없다.

### 그 밖의 수정

- 묘비(개인정보를 비운 비공개) 노트 upsert가 200으로 돌아오던 문제: `notesSyncService.classifyUpsertResult`로 저장 성공 여부를 판정하고, 묘비 응답이면 로컬을 정리한다.
- 새 번역 키 38개를 10개 언어에 추가했다.

## 자동 검증

- 앱 Jest 전체: 51개 묶음, 577개 테스트 통과 (2026-09-24 기준).
- iOS·Android Expo/Hermes 번들 생성 통과.
- 서버 테스트와 변경 내역은 서버 저장소 `docs/1.11.7-server-handoff.md` 참조.
- 에뮬레이터(Pixel 9, Android, 영어 UI) 화면 조작으로 2026-09-24에 확인한 항목 — 시험 계정 3개는 운영 서버에서 모두 삭제했고, 다른 사용자 자료 수치는 변하지 않았다.
  - 게스트 노트 작성 → 가입: 노트가 `::account:<authId>` 저장소로 이관되고 서버에 올라간다.
  - 프로필 공개 ON → 서버 행 공개. OFF → 서버 묘비(이름 익명·이메일 null·`profile_public=false`), 앱 재실행 후에도 비공개 유지.
  - 로그아웃 → 새 게스트 저장소, 이전 계정 자료 그대로 보존. 다른 계정 로그인 → 빈 저장소(남의 노트 안 보임).
  - 구버전(소유자 불명) 기록 주입 → `legacy-unassigned`로 격리, 프로필에 안내 표시 → 복구 화면에서 스위치 켠 뒤에만 옮기기 가능, 원본 보존, 안내 재표시 없음.
  - 오프라인(와이파이·데이터 끔)에서 노트 저장·삭제 → 온라인 복귀·포그라운드 시 새 노트 업로드, 삭제는 서버 `deleted=true` 묘비로 반영, 삭제한 노트 부활 없음.
  - 탈퇴(계정 2개): "삭제 완료" 안내, 게스트 상태로 복귀, 기기의 해당 계정 키 0개, 서버 auth·users·프로필·노트 모두 삭제. 다른 계정 자료는 유지.
- 확인하지 못한 것: 녹음 UI(에뮬레이터 마이크 없음), iOS 실기기, 한국어 자판 입력(에뮬레이터 IME 문제로 영어 UI에서 검증).

## 배포 전에 반드시 해결할 것

1. ~~**서버를 먼저 반영해야 한다.**~~ **해소.** 서버 브랜치를 main에 빨리감기 병합하고 프로덕션 배포를 마쳤다(서버 HEAD `0f75d22`). 앱이 요구하는 `/api/ai-analyze?stream=1&protocol=events`의 NDJSON 완료 이벤트가 운영에서 동작한다. 서버는 기존 plain 요청도 계속 지원한다.
2. ~~**운영 DB SQL은 아직 적용하지 않았다.**~~ **해소.** `migrations/2026-09-23-note-practice-meta.sql`(practice_meta, 삭제 부활 방지 트리거)을 2026-09-23 대표가 운영 DB에 적용했다. 서버 저장소의 `migrations/2026-09-23-profile-visibility.sql`도 함께 적용했다. 두 SQL은 실행 전 PGlite(실제 Postgres 엔진)로 각 10개 검사를 통과시켰다.
3. ~~**실제 회원 탈퇴는 미완성이다.**~~ **해소.** 서버 `api/account-delete.js`와 앱 `accountDeleteService.js`로 인증 계정·프로필·기록·소유 미디어까지 지우는 흐름을 구현했다. 시험용 계정 3개로 실서버 탈퇴를 검증했고(모두 정리 완료), 다른 사용자 자료에는 변화가 없었다. 부분 실패 시 users 행과 auth 계정을 남겨 다시 시도할 수 있다. 다만 아래 ‘남은 과제’의 제외 범위는 그대로다.
4. ~~**프로필 공개 OFF의 서버 저장과 동시 업로드 충돌**~~ **해소.** 서버가 공개 여부와 `visibility_updated_at`을 기록하고, 늦은 업로드와 구버전 업로드는 공개 여부를 바꾸지 못한다. 앱은 재시도·서버 상태 추종으로 재실행·다른 기기에서도 비공개를 유지한다. 실서버에서 확인했다.
5. **소유자 불명 구버전 기록의 복구 정책**은 여전히 미정이다. `LegacyRecoveryScreen`으로 본인 확인 후에만 옮기도록 했고 자료는 지우지 않았지만, 안내를 넘긴 사용자의 자료가 계속 표시되지 않을 수 있다. 본인 확인 없는 현재 계정 합치기는 계속 금지한다.
6. **기존 학습 텍스트·게스트 미디어는 삭제하지 않았다.** `training_data`(2026-09-24 기준 15,932행, 소유자 컬럼 없음)와 공통 `anon` 소유자로 보관된 게스트 미디어는 개인별로 골라낼 수 없다. 탈퇴·철회 응답의 `excludes`로 제외 범위를 안내만 한다. 식별·보존·삭제 정책은 정해지지 않았다.

## 남은 과제

- `training_data`와 anon 게스트 미디어의 개인별 삭제가 불가능하다. 정책 미정.
- 다른 기기에서 복원할 때 미디어와 재연습 체인은 복원되지 않는다(서버 컬럼 부재). 사용자에게 알리는 문구도 아직 없다.
- 검증 미완료: 녹음 UI, iOS 실기기. (가입·계정 전환·오프라인 저장·삭제 재동기화·탈퇴·복구 화면은 Android 에뮬레이터에서 확인 완료.)
- `ARCHIVE_COLLECTION_ENABLED`는 기본 미설정이다. 신규 학습 원본 수집은 중단된 상태이며 그대로 둔다.
